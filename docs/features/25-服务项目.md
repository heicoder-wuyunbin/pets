# 功能开发文档 · 25·服务项目

> 项目：宠老板复刻 · 里程碑：M4（F-041，P0）
> 作用：宠物服务项目库（美容/清洗/医疗等），作为收银可售服务的来源，并可被次卡绑定约。

---

## 1. 功能概述

实现**服务项目管理**：服务项目维护（名称、价格、时长、分类）、上下架，服务在收银台可作为 service 项结算，可由次卡绑定提供服务。

- 核心产出：服务 CRUD、上下架、服务列表。
- 前置：M0、Redis 号段、M1 鉴权；与 M5 次卡联动预留字段。

## 3. 需求明细

| 编号 | 功能点 | 说明 | 优先级 |
|------|--------|------|--------|
| R-01 | 服务分类 | 增删改 | P0 |
| R-02 | 服务 CRUD | 名称/价格/时长/描述 | P0 |
| R-03 | 上/下架 | status | P0 |
| R-04 | 次卡绑定预留 | `can_card` 字段 | P1 |

---

## 4. 表结构 `service`
| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint PK | 主键 |
| shop_id | bigint | 租户 |
| category_id | bigint | 服务分类 |
| name | varchar | 服务名 |
| price | decimal | 价格 |
| duration | int | 时长(分钟) |
| desc | varchar | 描述 |
| can_card | tinyint | 是否可用次卡 |
| status | tinyint | 1 上架 0 下架 |

## 5. 接口设计

- `POST /api/v1/service/save` / `status`。
